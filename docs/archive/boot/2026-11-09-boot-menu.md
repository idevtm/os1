# Two-entry boot menu

This change exposes the accepted logging profiles through two Limine entries.
Normal images start `os1` by default; `os1 diagnostics` selects additional tracing and larger logging budgets.

```text
Limine -> os1             -> normal logging
       -> os1 diagnostics -> diagnostic logging -> bounded /disk/log export
Dedicated capture image  -> diagnostics + existing reset-and-harvest workflow
```

## Plan and acceptance

1. Give each maintained Limine configuration exactly two entries: `os1` and `os1 diagnostics`.
2. Pass `os1.log=diagnostic` through the existing `BootInfo` command line for diagnostic selection.
3. Retain automatic capture selection in the dedicated keyboard-diagnostic image.
4. Verify menu selection, runtime ring capacity, tracing, and export profile metadata in QEMU.
5. Run configuration checks, relevant BIOS checks, and independent review.

Ordinary images show the menu for ten seconds and default to `os1`.
Dedicated keyboard-diagnostic images select the second entry immediately for unattended collection.
Only dedicated capture images add `os1.bootdiag`, which enables their existing watchdog and harvest behavior.
The custom BIOS loader has no menu; its existing build-selected profile remains unchanged.
Preserved-layout kernel updates retain their template configuration; a fresh image installs the new menu.

| Concurrency | Selects existing capture and export paths; adds no locks or ownership changes |
| Interfaces | Uses existing boot options and NativeLog status; preserves syscall and frame layouts |
| Runtime resources | Adds a ten-second ISO selection window; diagnostic logging uses the accepted memory and I/O budgets |

Affected requirements are GOALS `Scope and platform goals` and `Boot strategy`, architecture `Boot And Runtime Workflow`, and the accepted defaults in [context diagnostics](../../native-api/context-diagnostics.md#accepted-defaults--2026-11-08).
The [memory log ABI](../../native-api/abi/memory-log-abi.md) and [export ABI](../../native-api/abi/log-export-abi.md) define implemented behavior.
The Native API proposal does not assign new behavior through this menu change.

## Comparable measurements

The baseline restores revision `d0662a1` menu files into the candidate ISO while retaining identical kernel and initrd bytes.
This isolates menu selection from unrelated source-fingerprint changes.
[Raw measurements](2026-11-09-boot-menu-measurements.json) record samples, image sizes, source identity, and firmware hashes.
No other QEMU workload ran during these measurements.
Each profile uses three separate boots and twenty echo commands per boot.

| Median measurement | Baseline | Normal | Change | Relative change |
| --- | ---: | ---: | ---: | ---: |
| Automatic boot to shell | 1.900948 s | 12.131052 s | +10.230104 s | +538.16% |
| Twenty echo commands | 168.157 ms | 168.935 ms | +0.778 ms | +0.46% |
| Kernel ring capacity | 262144 bytes | 262144 bytes | 0 bytes | 0% |

The ten-second selection window accounts for the main automatic-boot increase.
Diagnostic boots select the second entry immediately; their 2.012291-second median includes simulated menu input.
Their twenty-command median is 181.276 milliseconds: 13.119 milliseconds, or 7.80 percent, above baseline.
These short TCG samples do not establish physical latency or a general performance change.

Diagnostic selection reports 1048576 bytes of ring capacity, an increase of 786432 bytes, or 300 percent.
All nine measurements report 168 slab pages; the ring uses separate page allocation.
The original prechange ISO and candidate ISO both contain 4448256 bytes, a zero-byte change.
The repacked timing-baseline ISO contains 4521984 bytes because xorriso rewrites its layout.
The candidate is 73728 bytes smaller than that measurement artifact, or 1.63 percent; this is packaging overhead, not a kernel reduction.
The raw image, kernel ELF, and initrd retain their original prechange byte sizes; each changes by zero bytes.
The existing export budgets select 250-millisecond drains, one-second dirty synchronization, and a 256 KiB/s framed-data ceiling.
Host tests from the export implementation cover these unchanged budgets; this task verifies runtime profile propagation.
No new scheduling, capture-lock, storage, or ownership algorithm is introduced.

The following procedure reconstructs the menu-only baseline and repeats the nine measurements.
Run it from the repository root after building the normal images.
It creates a new evidence directory and uses only test-owned disk copies.
The firmware and tool paths match the measured host.

```sh
python3 -B - <<'PYTHON'
import argparse
import shutil
import subprocess
import sys
import tempfile
import time
from pathlib import Path

sys.path.insert(0, str(Path('tests/scripts').resolve()))
from test_ext2_persistence import boot

evidence = Path(tempfile.mkdtemp(prefix='boot-menu-', dir='build'))
config = evidence / 'baseline.conf'
config.write_bytes(subprocess.check_output([
    'git', 'show', 'd0662a1:src/boot/limine/limine.conf']))
baseline = evidence / 'baseline.iso'
subprocess.run([
    'xorriso', '-indev', 'build/artifacts/os1.iso', '-outdev', str(baseline),
    '-boot_image', 'any', 'replay', '-map', str(config), '/limine.conf',
    '-map', str(config), '/EFI/BOOT/limine.conf'], check=True)
args = argparse.Namespace(
    qemu='/opt/homebrew/bin/qemu-system-x86_64',
    code='/opt/homebrew/share/qemu/edk2-x86_64-code.fd',
    vars='/opt/homebrew/share/qemu/edk2-i386-vars.fd',
    log=str(evidence / 'measure.log'), poweroff=True)
disk = evidence / 'measure.raw'
profiles = [('baseline', str(baseline), None),
            ('normal', 'build/artifacts/os1.iso', None),
            ('diagnostic', 'build/artifacts/os1.iso', 2)]
for label, image, selected in profiles:
    args.image = image
    args.boot_menu_entry = selected
    for sample in range(3):
        shutil.copyfile('build/artifacts/program-test-disk.raw', disk)
        def exercise(run, expect):
            print(run('os.system.log.info').decode().strip())
            print(run('kmem').decode().strip())
            start = time.monotonic()
            for i in range(20):
                run('echo "profile workload"')
            print(f'{label}-{sample}: echo_20_seconds={time.monotonic()-start:.6f}')
        boot(args, disk, f'{label}-{sample}', exercise=exercise)
print(evidence)
PYTHON
```
