## Assessment

The project now has working program, service, filesystem, and deployment paths.
The descriptor decision no longer blocks VFS, pipes, sockets, or PTYs at the foundation level.
Each additional service still needs its own authority, lifetime, completion, and failure contract.

Milestones A–C have implemented baselines. Milestone D has working storage but incomplete input services and local security.
Networking remains at the driver and ARP stage. Remote login and a compositor remain later milestones.
Hardware evidence covers specific observations, not general controller or machine qualification.

### Native API integration

The kernel provider table contains Console, Directory, and File providers.
Drivers remain kernel-resident, as selected for the current milestones.
A native object interface does not require a separate driver process.

Control records remain bounded at 256 bytes. Exclusive Buffers support larger user-provider exchanges, with a current 64 KiB limit.
Kernel Buffer borrowing needs an explicit internal borrower lifetime and access-completion rule.
A timeout ends the wait; it does not cancel accepted work or establish that a mutation did not occur.

Capability attachments and Buffer attachments remain separate envelopes.
Existing capability topology rules constrain service discovery, callbacks, and forwarding designs.
Start with a granted service directory and fixed registrations; prove the required topology before generalizing it.
Generated C++ bindings, general reflection, and client `.so` packaging remain tools, not prerequisites for input or storage services.

### Storage and hardware

USB ext2 mounting and reboot persistence work on the tested Asus EHCI hub path.
QEMU tests also cover preserving boot/program updates, removal, stale reconnect rejection, and transport failure.
Dedicated physical update-preservation and failure tests remain open.

The ext2 profile supports one block group, at most 128 MiB, and files up to 4,243,456 bytes.
Directories occupy one block. The managed USB data partition defaults to 128 MiB; it does not use the whole stick.
Multi-group allocation, directory growth, and host-validator changes must precede larger deployment profiles.
Ext2 has no journal. Successful `sync` establishes the documented durability boundary; interrupted metadata updates can require offline repair.

The block facade is internal C++, not a public native BlockDevice ABI.
Driver DMA ownership must remain separate from IPC Buffer ownership.
The device must stop accessing memory before the caller regains ownership or the kernel releases that memory.
Storage scheduling still needs measured work: polling, admission contention, sleeping workers, and monotonic timeout behavior.

### Input, security, and concurrency

The xHCI mouse handler counts reports but does not deliver usable pointer events.
The keyboard path feeds console characters; native key-state and pointer subscriptions remain unimplemented.
EHCI storage and high-speed hubs do not imply EHCI keyboard support.

The user confirms issue #27 still reproduces on a desktop with a USB keyboard connected to a USB 2.0 port.
Machine model, controller identity, keyboard identity, topology, and exact image revision remain unrecorded.
A USB 2.0 port alone does not establish whether the host path uses EHCI or xHCI.
Treat the original affected desktop separately from the successful Asus storage test.

Capability rights do not supply a complete multiuser identity or filesystem permission policy.
The ELF loader maps requested write/execute permissions without rejecting writable-executable segments.
Strict user-image W^X is a remaining hardening decision, not a claim of enforced behavior.
Credentials and access policy must precede multiuser or remotely exposed services.

ACPICA OSL locks remain no-ops; asynchronous execution is unsupported and the thread ID is constant.
Passive observation avoids the earlier power side effect but does not establish concurrent AML safety.
Broader runtime firmware and power services require serialization, authorization, driver quiescence, and recovery contracts.

Acknowledged Buffer mapping retirement does not prove every future shared-address-space teardown safe.
Keep generic reclamation, device IRQ affinity, and lock-order enforcement as separate reliability work.
This review identifies these extension limits without claiming a newly reproduced runtime defect.

These are implementation and acceptance priorities, not a new list of confirmed exploitable defects.

| Order | Priority | Completion evidence |
| --- | --- | --- |
| 1 | Physical update preservation and scheduler retest | An existing sentinel file survives boot-only and program-only updates and reboot; updated code runs; record exact image identity |
| 2 | Diagnose keyboard issue #27 | Identify the desktop controller and topology, reproduce the failing stage, and verify shell input after correction |
| 3 | Native input services | Two independent clients receive future key/mouse events; unsubscribe, overflow recovery, removal, and console input pass |
| 4 | Scoped discovery and service lifecycle | Explicit startup grants, attenuated lookup, supported capability topology, and defined stop/restart results |
| 5 | Kernel bulk I/O and device objects | A concrete client uses retained Buffers; access ends before return; public BlockDevice authority and failure rules are tested |
| 6 | Larger persistent storage | Expanded ext2 and deployment validation preserve files across update and reboot; unsupported layouts remain rejected |
| 7 | Pipes and local security | Readiness/backpressure and pipeline teardown work; credentials, ownership, and permissions reject unauthorized access |

Hardware acceptance can proceed alongside source work.
Input objects do not require generated bindings, a universal registry, or userspace drivers.
Later extensions include additional Buffer sharing modes, richer reflection, a terminal compositor, broader storage controllers, and architecture ports.
