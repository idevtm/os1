## 1. Assessment

`os1` now has a more credible path from QEMU to a particular physical machine.
Booting without COM1, bounded serial polling, firmware timing, PCI failure
isolation, and preservation of a known-working USB layout address failures
that emulator-only development did not expose. These are substantive runtime
improvements since the May review.

The user-facing system has progressed less. The native API work is still a
set of proposals and reviews. Processes still load programs directly from the
initrd, the syscall set remains small, and there is no implemented descriptor
table, VFS namespace, credential model, or general network stack. The next
feature milestone should be a small, tested process-resource contract, followed
by console descriptors and an initrd-backed VFS.

Correctness work must precede that expansion. This review identifies a
post-publication child-frame write, an observation syscall that changes device
power state, an unchecked exception-stack allocation, a smoke-runner
success condition that overstates its settle interval, and a page-frame leak
when mapping fails. The previously observed
intermittent BIOS child-launch fault remains unresolved. Passing CI is useful
evidence, but does not dispose of these findings.

## 2. Scope and evidence

The review inspected the current boot, platform, process, scheduler, memory,
syscall, UAPI, userland, storage, and network sources; host/script tests; CMake
and CI; goals; and the dated hardware and API documents. Findings below separate
source-confirmed behavior, observed execution, and hypotheses.

The reviewed branch includes main's November boot changes and PR #24's
additional documentation. The implementation under `src/user`, `src/uapi`, and
`src/kernel/{proc,syscall,fs,vfs,security,storage}` is unchanged from `7b0094c`.
The [unified API review](os-api-draft/2026-05-10-unified-os-api-architecture-review.md)
therefore improves design clarity without implementing that design.

The harness work in [PR #25](https://github.com/idevtm/os1/pull/25), reviewed
separately at `cc99939`, is **not present in this source snapshot**. In particular,
this branch has no `tools/verify.sh`, `AGENTS.md`, or `doc/README.md`. Its proposed
checks, structured smoke summaries, and maintenance records must not be counted
as current main/native-api capabilities.

## 4. Priority findings

Priorities here describe engineering urgency in this project, not a claim that
every finding has been reproduced as an end-user failure. P1 means address
before expanding the affected runtime capability; P2 means a concrete hardening
or validation follow-up. This review makes no implementation changes.

### R1 — P1: child entry state is rewritten after scheduler publication

**Source-confirmed ordering defect; connection to the BIOS fault is unproven.**

[`load_user_program`](../src/kernel/proc/user_program.cpp#L185) calls
`create_user_thread(..., start_ready)` and then calls `prepare_user_thread_entry`.
The latter clears the wait state and zeroes/rebuilds `thread->frame` at lines
149–158. With `start_ready=true`,
[`create_user_thread`](../src/kernel/proc/thread.cpp#L587) has already made the
thread runnable. `mark_thread_ready` enqueues it and can send a reschedule IPI
to another CPU at lines 623–635.

The run-queue lock is released before the caller rewrites the frame. An AP can
therefore dequeue the child and restore that embedded frame, or save a newer
frame after execution, while the creator is clearing it. Masking interrupts on
the spawning CPU does not prevent the AP from running. The ordinary
[`sys_spawn` path](../src/kernel/syscall/process.cpp#L63) uses the default
`start_ready=true`; initial boot deliberately uses a non-ready first thread.

**Next action:** make the enqueue/IPI operation the final publication step,
after all entry and ownership state is complete. Add a regression that forces
an AP to consume the child at the publication boundary. Retain the BIOS failure
as separate evidence until a controlled before/after experiment links it to this
race. Do not label the launch fault solved merely because this ordering is fixed.

### R2 — P1: ACPI observation performs ungated power transitions

**Source-confirmed side effect; no destructive hardware test was attempted.**

[`sys_observe_acpi`](../src/kernel/syscall/observe.cpp#L957) attempts D3 followed
by D0 on an active PCI binding's ACPI companion. Its fallback tries other active
power-capable ACPI devices at lines 978–980.
[`sys_observe`](../src/kernel/syscall/observe.cpp#L994) checks for a current
thread and dispatches the request without a credential or diagnostic-mode gate.
There is no driver-quiescence protocol around these transitions. If D3 succeeds
and D0 fails, the operation records failure without establishing recovery.

The May review framed observe-access policy mostly as a future multiuser
problem. This operation already has a physical side effect in the current
single-user system: a ring-3 diagnostic can disrupt a live device. An API named
as a snapshot must not silently carry that authority.

**Next action:** separate passive ACPI snapshots from explicit power diagnostics;
require a deliberate authorization/diagnostic boundary and driver coordination
for the latter. Test that ordinary observation never invokes power methods and
that failure after D3 follows a defined recovery policy. This finding is not
asserted to explain the `acpiprobe` launch crash.

### R3 — P2: IST allocation failure leaves fatal exceptions without their stack

**Source-confirmed failure path; allocation failure was not injected.**

[`cpu_init`](../src/kernel/arch/x86_64/cpu/cpu.cpp#L150) sets `tss.ist1` only if
page allocation succeeds, then continues regardless. The
[IDT initialization](../src/kernel/arch/x86_64/interrupt/interrupt.cpp#L164)
unconditionally assigns IST1 to NMI, double fault, and machine check. If a CPU
has no existing IST stack and allocation fails, those handlers are configured
against a zero stack pointer, defeating the new containment path.

**Next action:** require a valid per-CPU exception stack before enabling that
IDT configuration, or define an explicit safe fallback. Verify the allocation
failure path for both BSP and AP initialization.

### R4 — P2: smoke runner reports a completed settle period after early exit

**Reproduced on the reviewed revision with a short-lived subprocess.**

The reader sets `done` on EOF. The main loop then proceeds to success if all
markers were seen, without requiring the settle deadline to have elapsed
([runner lines 285–352](../cmake/scripts/run_smoke.py#L285)). The command below
exits successfully almost immediately while claiming a clean one-second window:

```sh
python3 cmake/scripts/run_smoke.py \
  --log /tmp/os1-review-early-exit.log --timeout 2 \
  --settle-after-markers 1 --marker READY -- \
  python3 -c 'print("READY", flush=True)'
```

Observed output:

```text
Smoke run matched all 1 markers and stayed clean for 1.00s.
```

This demonstrates a runner contract defect, not a QEMU crash. A guest/emulator
that disappears after its final required marker can be accepted without the
advertised clean interval. The corresponding explicit settle-completion check
exists in the separately reviewed harness branch, but is absent here.

**Next action:** land the corrected runner with a regression for early EOF
during settling, keeping timeout, forbidden-marker, and failure behavior intact.
Reconcile the no-UART test metadata when integrating the harness work.

### R5 — P2: mapping failure leaks an allocated data frame

**Source-confirmed failure path; allocator exhaustion was not injected.**

[`VirtualMemory::allocate_and_map`](../src/kernel/mm/virtual_memory.cpp#L265)
allocates and clears a data frame before calling `map_physical`. If mapping fails,
for example because an intermediate page-table allocation runs out of memory,
the function [returns false](../src/kernel/mm/virtual_memory.cpp#L275) without
freeing that frame. The frame has not been linked into a page table, so later
address-space destruction cannot find and reclaim it. Repeated failures can
therefore consume additional physical memory while the caller is already
handling an allocation failure.

**Next action:** release the unlinked data frame when mapping fails and define
the rollback contract for earlier pages in a multi-page request. Inject failure
after data-frame allocation but before a required page-table allocation, then
verify that teardown restores the starting free-frame count.

## 5. Current capability and remaining contracts

### Process resources and native API

The [nine syscall numbers](../src/uapi/os1/syscall_numbers.h) cover console I/O,
exit/yield/getpid, observe, spawn/waitpid/exec. Console fd 1/2 are special cases
in [sys_write](../src/kernel/syscall/process.cpp#L11), not entries in a process
resource table. [Process](../src/kernel/proc/process.hpp) has no implemented
credentials or descriptor ownership. The loader resolves paths through initrd,
and [the user entry point](../src/user/lib/crt0.cpp) calls `main(void)`.

The useful next decision is the minimum descriptor/handle contract: identity
and reuse, ownership, rights, close/dup semantics, per-open state, errors, and
spawn/exec inheritance. The larger reflective object system, typed values,
interface discovery, and event model remain design directions. Their existence
in a draft should not force the first console/VFS slice to implement the entire
object catalog. Bounded argv/envp design can proceed alongside the resource work.

### SMP, memory, and lifetime

Per-CPU scheduling, wakeups, run queues, the page-frame lock, kernel allocation,
and user-copy validation are real infrastructure. They are not a proof of the
publication and lifetime rules above. Host tests exercise substantial real
kernel code but also substitute CPU, physical-memory, and hardware behavior.

[TLB shootdown callers](../src/kernel/mm/virtual_memory.cpp#L33) exist, but the
[IPI interface](../src/kernel/arch/x86_64/apic/ipi.cpp) broadcasts invalidations
without an address-space/range completion protocol. The May review's assertion
that broadcast is simply “correct” should not substitute for a reclamation
proof. Establish when pages can be reused, which CPUs may still reference an
address space, and what completion means before adding shared address spaces,
COW, or user mapping operations. This review does not prove a specific stale-TLB
failure. Lock-tier enforcement and cross-CPU stress remain follow-ups; AP-targeted
device IRQ steering is useful, but less urgent than lifecycle correctness.

### Storage and networking

[Block requests](../src/kernel/storage/block_device.hpp) and completion-backed
read/write paths exist. Virtio block bounds a request to eight sectors and
[rejects Flush](../src/kernel/drivers/block/virtio_blk.cpp#L404). Successful write
completion is not a persistent-storage durability contract. Implement a read-only
initrd VFS first, then define flush, ordering, error, and crash behavior before
a writable block-backed filesystem.

[Networking](../src/kernel/drivers/net/virtio_net.cpp) is a working virtio device
path plus ARP parsing/cache/probe, with QEMU-oriented fixed addresses and a small
buffer arrangement. It is not a general IP/UDP/TCP/socket stack. Packet ownership,
receive buffering, monotonic deadlines, and cancellation must precede protocol
expansion. SSH additionally needs credentials, entropy, PTYs/sessions, and
process supervision; `/bin/init` currently just execs the shell.

### ACPICA and timing

The upstream interpreter is valuable, but its presence does not make the OS
adapter complete. The [OSL](../src/kernel/platform/acpica_osl.cpp#L201) still has
dummy locks, nonblocking semaphore behavior, a constant thread ID, and unsupported
async execution and interrupt-handler operations. Those limitations constrain
concurrent AML, SCI/GPE handling, and broader power management. Calls from
multiple runnable processes make an explicit serialization model relevant now,
not merely when an asynchronous API is added.

The [TSC helper](../src/kernel/drivers/timer/tsc_clock.cpp#L94) fixes useful
firmware timing paths; its calibration-failure timer advances by queries, and
it provides no demonstrated cross-CPU monotonicity contract. Preserve the
distinction between firmware wait support and a public clock/deadline facility.

### Physical hardware and persistent diagnostics

The [G74SX record](2026-11-02-g74sx-bringup-debug-plan.md) distinguishes a reported
round-8 success from the final early-buffer fix, which postdates that report.
Detailed command results, sustained responsiveness, and eight-CPU observations
remain requested evidence. A fresh round-7 image passed QEMU yet was absent from
the firmware menu. The preserved-layout update path is therefore the established
experiment boundary, not proof that arbitrary regenerated media will boot.

The [kernel-only updater](../cmake/scripts/update_usb_kernel.py) checks an exact
40 MiB base image and a fixed 650,952-byte kernel extent, compares the full and
stripped ELF load contracts, preserves bytes outside the extent, rejects output
aliases, and replaces the output atomically. Its narrowness is appropriate to
the evidence. Boot-chain or userspace changes need a separate qualification step.

[Boot-log writes](../src/kernel/debug/bootlog.cpp#L46) reserve positions before
storing bytes. Another CPU can advance the persistent flush cursor first; a
reset can lose a late store. The [documented caveat](2026-11-02-real-hardware-bootlog.md#caveats)
already acknowledges this. Treat capture as best-effort until a completion-safe
flush protocol and physical reset tests exist. The normal smoke ISO does not
exercise the persistent preloader/log-recovery chain.

## 6. Documentation and verification corrections

The older reviews are dated snapshots and should remain intact. Their assertions
must be interpreted against their original revisions, with these updates:

- The no-op ACPICA waits/frozen timer concern is partly closed for freestanding
  builds; the public time API and fallback accuracy concerns remain open.
- Real-device work is now merged into the runtime baseline. It should no longer
  be described solely as an unmerged investigation branch.
- ACPICA probe behavior **is** asserted by both observability smokes:
  [UEFI markers](../CMakeLists.txt#L1038) and [BIOS markers](../CMakeLists.txt#L1342)
  include route/power output. The May review's contrary coverage statement is
  not accurate for this revision. The power marker permits an unavailable result;
  it does not establish successful power management on every platform.
- At the reviewed revision, [Architecture's smoke inventory](ARCHITECTURE.md#smoke-tests)
  described eleven shell smokes. With CI's `OS1_QEMU_DEBUGCON=ON`, registration
  includes the no-UART smoke and two script contracts: 14 CTest cases in total.
  Without that option, no-UART is not registered. Test counts must name their
  configuration.
- The ACPICA documentation refresh and latest-review maintenance requested in
  May have been performed. Descriptors, argv/envp, VFS, credentials, and network
  protocols have not been implemented by that documentation work.
- Current [CI](../.github/workflows/ci.yml) builds/tests directly. The unified
  verification, artifact summaries, dependency checks, and scheduled health
  reports belong to the unmerged harness work. Integrating it requires indexing
  the Native API review documents and this review, and reconciling architecture
  metadata; do not solve index failures by weakening the check.

Same-day documentation follow-up: the live README, goals, architecture, SMP
contract, ACPICA status, hardware guidance, and subsystem READMEs now incorporate
these status corrections, including the option-dependent test inventory. The
runtime findings and the unresolved BIOS failure remain open; documentation
updates do not change their validation status.

## 7. Recommended next milestones

| Order | Deliverable | Acceptance evidence |
| --- | --- | --- |
| 1 | Finish child initialization before publication; investigate the BIOS fault. | Deterministic publication-boundary regression, preserved failing evidence, and controlled before/after SMP runs. Passing retries alone do not close the fault. |
| 2 | Make ordinary ACPI observation passive; constrain power diagnostics. | Tests proving no power-method calls from snapshot reads; explicit authorization/quiescence and failure recovery for diagnostics. |
| 3 | Close IST allocation failure, mapping-failure leaks, and smoke-runner false success. | Allocation-failure and rollback coverage; early-EOF/settle regression; no-UART and monitor contracts retained. Integrate reviewed harness work rather than duplicate it. |
| 4 | Qualify the exact current kernel on the preserved G74SX image. | Recorded image/kernel hashes, command/input results, CPU observations, and sustained runtime; separately qualify diagnostic reset/log recovery. |
| 5 | Approve a minimal descriptor contract and implement console entries 0/1/2. | Invalid-handle, rights, duplication, close, inheritance, and teardown tests plus unchanged basic shell behavior. |
| 6 | Add bounded argv/envp and a read-only initrd VFS; route exec through it. | Argument handoff, lookup/error, lifetime, and exec regressions across both boot paths. |
| 7 | Establish persistence and networking prerequisites, then choose one vertical slice. | Storage flush/error semantics for writable FS; clock/deadline and packet ownership for networking. Add credentials/access policy before multiuser or network-exposed operations. |

Work on the descriptor decision and documentation can proceed while reliability
bugs are isolated. Broadening runtime state, hardware power operations, or
concurrent resource ownership should wait for their respective safety contracts.
GUI, remote login, additional storage transports, and wider autonomous maintenance
are downstream work, not substitutes for these gates.

## 8. Reproduction and review limits

To reproduce the reviewed build/test configuration with the documented tools
and initialized submodules:

```sh
cmake -S tests/host -B build-host-tests -G Ninja \
  -DCMAKE_BUILD_TYPE=Debug -DOS1_KMEM_DEBUG=ON
cmake --build build-host-tests
ctest --test-dir build-host-tests --output-on-failure --no-tests=error
cmake --preset default -DOS1_REQUIRE_UEFI_SMOKE=ON \
  -DOS1_KMEM_DEBUG=ON -DOS1_QEMU_DEBUGCON=ON
cmake --build build --target os1_image os1_bios_image
ctest --test-dir build --output-on-failure --no-tests=error
```

The source findings require focused follow-up validation. This review is not a
formal memory-safety proof, hardware certification, acceptance of the draft ABI,
or a claim that every subsystem was exhaustively audited. It records the current
capabilities, concrete hazards, known failed evidence, and the next useful tests
at the stated revision. The older reviews remain available as history through
[latest-review.md](latest-review.md).
